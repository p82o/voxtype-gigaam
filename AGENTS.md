# AGENTS.md — GigaAM v3 для voxtype через Docker

Перед изменением файлов или установленной системы согласуйте план с пользователем.
Явное «делай» разрешает реализацию согласованного плана.

## Назначение и установка с нуля

Репозиторий устанавливает GigaAM v3 e2e RNN-T для уже установленного voxtype:
FastAPI и CPU-модель работают в Docker, watchdog — в systemd user session.
Прежний GigaAM, venv и локальные веса не требуются. Отката и резервных копий нет.

1. Прочитайте раздел «Требования и установка» в README.md: там подготовка Docker,
   Compose/Buildx, доступа из systemd user manager, конфигурации voxtype и порта.
   Если Docker отсутствует, подготовьте его в рамках разрешённой установки;
   отсутствие предпосылки требует её устранения, а не завершения задачи.
2. Проверьте Linux amd64, доступ к Docker, Compose/Buildx, systemd user session
   целевого пользователя и его voxtype service. ASR не требует Python/ffmpeg хоста.
   Docker должен запускаться при загрузке; его команды должны работать как из
   пользовательского shell, так и из user unit. После добавления группы docker
   переоцените доступ из user manager по проверке в README, а не только в shell.
3. Подготовьте `~/.config/voxtype/config.toml` с рабочим `[hotkey]` пользователя.
   Если клавиша неизвестна, спросите её. `config/voxtype-config.toml` — пример
   ASR-настроек без hotkey и микрофона; используйте его как справочник, сохраняя
   существующую конфигурацию. Для первого запуска настройте voxtype в его
   графической сессии; инструкция установки самого voxtype здесь не дублируется.
4. Запустите `./install.sh` от пользователя сессии, затем `./verify.sh`.
   Установщик скачивает и проверяет код/веса, собирает и аудирует образ, загружает
   модель offline, создаёт контейнер и user units, сливает настройки voxtype.
   Установленный стек — `~/.local/share/gigaam/docker/`, watchdog — `~/.local/bin/`.
5. Полная проверка временно останавливает/удаляет/замораживает только контейнер ASR.
   `--skip-watchdog` годится для диагностики; первую полную приёмку им не заменяйте.
   Если шаг не прошёл, используйте таблицу «Если установка не завершилась» в README,
   исправьте причину и повторите нужный шаг. Затем проверьте критерии ниже.
6. Пользователь проверяет push-to-talk, распознавание и вставку в реальном приложении.
   Автоматический `voxtype transcribe` не проверяет доступ к клавише или вставке.
   Отдельно сообщите, если эта ручная проверка ещё не выполнена.

Критерии завершения:

1. Контейнер `gigaam-asr` использует установленный image ID, `restart: always`,
   UID/GID 10001 и публикует порт только на `127.0.0.1:8394`; `/health` возвращает 200.
2. `gigaam-watchdog.timer` активен, Docker daemon включён при загрузке системы.
3. Аудио 25.003 секунды не зависает; официальный пример и 60 секунд речи распознаются.
4. Docker восстанавливает завершившийся процесс; watchdog восстанавливает остановку,
   отсутствие контейнера и зависание. Перезагрузка хоста отдельно согласовывается.
5. voxtype активен, использует ожидаемый remote endpoint, транскрипция успешна.
6. SHA-256 секции `[hotkey]` совпадает с `hotkey.sha256`, сохранённым установщиком.

## Ограничения реализации

- Сохраняйте пользовательский `[hotkey]` побайтово; меняйте только нужные ASR-ключи.
- Обновляйте CPU torch/torchaudio согласованной парой через `scripts/update-lock.sh`;
  после обновления проверяйте загрузку и распознавание. Runtime устанавливается из
  полного lock с хешами; Transformers, VAD, обучение и ONNX для inference не нужны.
- Используйте неизменённые исходники официального GigaAM на commit из `model/`.
  Архив кода, native checkpoint и токенизатор проверяются по SHA-256; модель внутри
  образа. Длинное аудио обрабатывается собственными чанками сервера.
- `scripts/audit.sh --image IMAGE` обязателен до запуска устанавливаемого ASR.
  Ошибка сети, неполный отчёт и пропуск пакета блокируют переключение. Для Python
  блокируется каждая неисключённая находка; для Debian — HIGH/CRITICAL с доступным
  исправлением. Остальные Debian-находки сохраняйте в полном отчёте и показывайте
  при установке. Исключения привязаны к пакету/версии/ID и имеют срок пересмотра в
  `security/exceptions.json`; причины и команды проверки — в разделе аудита README.
- Сохраняйте RLock и lock-aware `/health`, двойную проверку watchdog 15/5/15 секунд,
  startup grace и ожидание готовности после восстановления.
- Контейнер восстанавливается из установленного Compose/image ID без сборки и pull.
  При недоступном Docker watchdog повторяет проверку позже; чужой контейнер не трогает.
- Запускайте рабочий ASR по установленному Compose-описанию на штатном порту;
  офлайн smoke-load проверяет модель без HTTP listener.
- Доступ к микрофону и вводу остаётся в voxtype хоста; ASR получает только HTTP-аудио.
- Диагностика не выводит конфигурации, credentials, текст речи и сырые исключения.
- Права администратора нужны для подготовки системных предпосылок Docker
  в рамках разрешённой установки; `install.sh` запускается от целевого пользователя.
  Микрофон и его усиление меняйте только по просьбе пользователя; сохранение через
  `alsactl store` также требует прав администратора.

При зависании inference, пустой транскрипции или шуме микрофона прочитайте
результаты проверенной Docker-сборки и диагностику: `docs/notes-ru.md`.
